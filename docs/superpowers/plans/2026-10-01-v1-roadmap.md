# Open Desktop Remote V1 — 实施路线图

**Spec:** `docs/superpowers/specs/2026-10-01-open-desktop-remote-design.zh-CN.md`

V1 拆成四份独立、按顺序执行的实施计划。每份计划都必须在自己的测试门槛通过并提交后，才能进入下一份；不要跨计划提前实现未来功能。

## 执行顺序

1. **Foundation & Protocol**
   - `docs/superpowers/plans/2026-10-01-v1-foundation-protocol.md`
   - 产物：monorepo、协议 schema、错误码、设备状态机、协议协商。
   - 不包含网络和持久化。

2. **Auth & Control Plane**
   - `docs/superpowers/plans/2026-10-01-v1-auth-control-plane.md`
   - 产物：Fastify Server、SQLite、单 Owner bootstrap、OAuth + PKCE、DCR、设备配对、设备注册/撤销。
   - 不包含 Relay 和工具执行。

3. **Relay, Agent & Desktop Commander Adapter**
   - `docs/superpowers/plans/2026-10-01-v1-relay-agent-adapter.md`
   - 产物：outbound WSS、Agent、credential storage、Desktop Commander stdio bridge、READY 状态、重连、去重、取消、`EXECUTION_UNKNOWN`。
   - 到本阶段结束，Server 与 Agent 已能完成真实远程工具 RPC，但还没有公开 MCP Gateway。

4. **MCP Gateway, Dashboard & Deployment**
   - `docs/superpowers/plans/2026-10-01-v1-mcp-dashboard-deploy.md`
   - 产物：标准 MCP Streamable HTTP、OAuth resource protection、Desktop Commander 一等工具、多设备路由、Dashboard、日志脱敏、Docker/Caddy、E2E、跨平台 CI 和完整文档。
   - 本阶段结束即达到 V1 spec 验收线。

## 已锁定的关键实现选择

- Node.js 24 + TypeScript + pnpm workspaces。
- Fastify 5 作为自托管 Server HTTP/WebSocket 框架。
- MCP TypeScript SDK v2，对应 2026-07-28 MCP 规范。
- SQLite + better-sqlite3。
- 内置单 Owner OAuth Authorization Server；Authorization Code + PKCE S256。
- DCR 作为 ChatGPT 连接的 V1 客户端注册路径。
- `@jmondi/oauth2-server@5` 承载 OAuth 协议核心，项目自己持久化 client/code/token。
- Agent credential 优先使用 `@napi-rs/keyring`，不可用时退回 user-profile scoped 文件。
- Desktop Commander V1 compatibility pin：`@wonderwhy-er/desktop-commander@0.2.52`。
- Server ↔ Agent 使用项目自有、公开、版本化的 WSS Relay Protocol；不依赖 frp/Supabase。
- MCP 层保持 stateless；设备在线和 executor 状态属于应用 Relay 层。
- 默认不记录 payload，不发第三方 telemetry。
- Apache-2.0。

## 变更规则

实现中如果出现下列情况，停止当前任务并先更新 spec/plan：

- Desktop Commander 0.2.52 无法通过标准 stdio MCP 与官方 MCP v2 Client 正常互操作；
- ChatGPT 当前 OAuth 行为与 DCR + PKCE 的测试环境存在不可兼容差异；
- 某项安全要求只能通过新增强制第三方 SaaS 才能完成；
- 为通过测试必须引入离线队列、自动重放、云文件缓存、多用户等明确超出 V1 的能力；
- 协议需要 breaking change，且无法通过 version negotiation 保持当前 V1 定义。

## V1 最终质量门槛

最终合并前必须同时通过：

```bash
pnpm test:run
pnpm typecheck
pnpm test:e2e
docker compose config
docker build -t open-desktop-remote:test .
git diff --check
```

并完成 Windows、macOS、Linux Agent smoke CI。

任何测试失败都不能以“文档说明已知问题”的方式绕过 V1 验收。
