### Confirmed defects and changes

- **P2, initialization failure reported as successful cancellation:** a physical
  close observer ran before the SDK rejected its pending initialization request.
  Manager invalidation aborted the SDK, and its catch discarded every error when
  the signal was aborted. The manager now records one attempt outcome separately
  from the cancellation signal. Deliberate cancellation releases pending work;
  unexpected close releases the manager's wait as a failure while allowing the
  SDK to report its original error. Mandatory shared cleanup can expose the
  original factory rejection. A first startup failure survives later stop,
  replacement or incompatibility, and finished attempts cannot change newer
  state. Cleanup failure retains both causes and the existing replacement fence.
- **P2, stop did not cancel token-refresh I/O:** the signal now reaches native
  fetch and response-body consumption through runtime, Relay, token refresh and
  ServerClient. The adjacent first-pairing create/poll/timer and WebSocket
  establishment paths receive the same signal. Relay owns a returned socket
  before awaiting executor startup, terminates it on stop, and awaits physical
  close with error coverage intact. An injected legacy close waiter cannot hold
  shutdown after that socket closes. Saved credentials are preserved.
- **P2, a neighboring Relay catch also suppressed unrelated failure on stop:**
  Relay now recognizes the actual cancellation reason instead of treating every
  error after abort as a successful stop. Additional real MCP/runtime tests
  prove that the original initialization error survives a simultaneous stop.
- **P3, concrete Relay executor dependency:** a seven-method `RelayExecutor`
  interface expresses only consumed capabilities. The test double explicitly
  satisfies that interface; the double assertion and its `as never` state
  assignment are gone. Runtime continues to own final physical shutdown.

The existing transport's final-SIGKILL cleanup, callable/owned client separation,
epoch guards, runtime identity, tool metadata and contracts, installed CLI smoke,
and unknown-operation no-replay behavior remain in place. No dependency or public
wire-protocol change was introduced, and no official upstream files were changed.

network/Relay patch. The former independently ran 100 relevant tests and probes

The bounded diagnostic rule is deliberate: an opaque injected factory that
withholds its rejection beyond mandatory cleanup receives a generic close
failure. Its late diagnostic cannot rewrite a returned result or a replacement.
The supported direct Adapter path preserves the actual SDK error. Likewise,
custom network factories must honor the supplied signal while privately owning
resources; Relay cleans a legacy socket as soon as it is handed over.
